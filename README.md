17. قوانین مهم توسعه

- قبل از نوشتن کد، ساختار موجود پروژه را بررسی کن.
- اگر به فایل نسخه ۲.۱ دسترسی داری، ابتدا آن را کامل بخوان.
- قابلیت‌های موجود را بدون دلیل حذف نکن.
- کد جدید را بدون بررسی و تست تحویل نده.
- از ساختارهای غیرضروری و پیچیده استفاده نکن.
- هیچ API Key یا توکنی را داخل سورس قرار نده.
- از مدل‌ها و Endpointهای منسوخ استفاده نکن.
- برای قابلیت‌های Gemini از مستندات رسمی جدید استفاده کن.
- برای تلگرام از مستندات رسمی Telegram Bot API استفاده کن.
- اگر قابلیتی به دلیل محدودیت API قابل اجرا نیست، صادقانه اعلام کن.
- هیچ تستی را که واقعاً انجام نداده‌ای، موفق اعلام نکن.
- اگر امکان ساخت فایل وجود دارد، فایل نهایی را ایجاد کن و لینک واقعی تحویل بده.
- اگر امکان ساخت یا اجرای فایل وجود ندارد، محدودیت را شفاف اعلام کن.
- به جای تحویل کد ناقص، ابتدا معماری را مشخص کن و سپس مرحله‌به‌مرحله توسعه بده.

نتیجه نهایی باید یک دستیار هوش مصنوعی شخصی به نام MSGN AI 2.2 باشد که بتواند از طریق ترمینال Termux با کاربر تعامل کند، حافظه دائمی داشته باشد، فایل‌های تلگرام را دریافت و تحلیل کند، پروژه‌های برنامه‌نویسی را بفهمد، با Gemini گفتگو کند و تصویر تولیدشده را مستقیماً به تلگرام ارسال کند.

اکنون توسعه پروژه را شروع کن.
